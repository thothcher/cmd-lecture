01 / Two ways

Two Ways to Talk to a Computer

GUI · Desktop

Graphical User Interface

You point and click on things the OS draws for you: windows, icons, menus. Every option is visible.

Example

Double-click › Projects folder

CLI · Terminal

Command-Line Interface

You type a command and press Enter. The computer answers in text. Fast, precise, repeatable.

Example

C:\Users\you> cd Projects

There are two ways to tell a computer what to do. The first is the GUI, the graphical user interface: the desktop, windows, icons, menus and the mouse pointer. The operating system draws every option for you, so you can discover things just by looking. The second is the CLI, the command-line interface: you type a command as text, press Enter, and the computer answers with text. Nothing is drawn for you, so you have to know what to ask, but once you know, it is very fast and very precise. Both examples on the slide do exactly the same thing: open the Projects folder. Ask the class: which one do you use every day? Almost everyone says the GUI. By the end of today you will see why professional developers use both.

02 / Vocabulary

Terminal, Shell and Kernel

Layer 1 · window

Terminal

Draws text, captures your keys, handles tabs, fonts and colors. It does not understand commands.

Windows Terminal, iTerm2, VS Code

Layer 2 · interpreter

Shell

Reads the line you typed, expands variables, finds the program and asks the OS to start it.

cmd.exe, PowerShell, Bash, Zsh

Layer 3 · core

OS Kernel

Creates processes, manages memory and files, talks to the hardware. The desktop uses this same kernel.

Windows NT, macOS XNU, Linux

Prompt

The shell's way of saying "ready for your command":

C:\Users\you>   PS C:\Users\you>   you@laptop:~$

Console

The older word for a program's text input and output. On Windows, the classic console window is conhost.exe.

Students mix these words up all the time, so let's fix them once. The terminal is only a window: it shows text, captures your keystrokes, and handles tabs, fonts and colors. It does not understand a single command. Inside the terminal runs a shell. The shell is the interpreter: it reads the line you typed, expands variables, finds the right program and asks the operating system to start it. CMD, PowerShell, Bash and Zsh are all shells. Below everything sits the kernel, the core of the operating system, which actually creates processes, manages memory and files, and talks to the hardware. A simple analogy: the terminal is a chat app, the shell is the person you are chatting with, and the kernel is the team that actually does the work. Two more words: the prompt is the text the shell prints when it is ready, like C:\Users\you> in CMD or a dollar sign in Bash. Console is an older word for a program's text input and output; on Windows the classic black console window is conhost.exe.

CMD, short for cmd.exe, is the Windows Command Prompt. It is a shell: it reads what you type and runs it. It can also run batch scripts, files ending in .bat or .cmd, which are simply lists of commands. Its family tree goes back to COMMAND.COM in MS-DOS in 1981. cmd.exe itself appeared in OS/2 in 1987 and came to Windows with Windows NT in 1993. In 2006 Microsoft released PowerShell as its modern successor, and today Windows 11 opens Windows Terminal with PowerShell by default. But CMD is still installed on every Windows PC, it starts instantly, and it is perfect for learning the basics. On the right is a real session: we move into a folder with cd, list the files with dir /b, where /b means bare names only, and print text with echo. Point out the prompt: it always shows the folder you are in.

What Happens When You Click or Type

Desktop road · double-click the VS Code icon

1Input event

Your click reaches Windows as an input message

2explorer.exe

The GUI shell works out which icon you hit

3API call

ShellExecute, then CreateProcess for Code.exe

Terminal road · type node app.js + Enter

1Keystrokes

Windows Terminal hands your line to cmd.exe

2Parsing

Program: node. Argument: app.js

3PATH lookup

Finds node.exe, then calls CreateProcess

Both roads end here

OS Kernel

Creates the process, gives it memory, opens files and schedules the CPU.

Then the GUI app draws a window, and the CLI app prints text to stdout.

The desktop is a program too: explorer.exe is literally called the Windows shell. On macOS and Linux, shells start programs with fork() and exec(): different names, same idea.

This is the most important technical idea of the lecture. Follow the top road first. You double-click the VS Code icon. The mouse click arrives in Windows as an input message. explorer.exe, the program that draws your desktop and taskbar and is officially called the Windows shell, figures out which icon you clicked. It then calls a Windows API, ShellExecute, which ends in CreateProcess for Code.exe. Now the bottom road. You type node app.js and press Enter. Windows Terminal passes that line to the shell, here cmd.exe. The shell splits it into the program, node, and the argument, app.js. It searches the folders listed in the PATH variable, finds node.exe, and calls the very same CreateProcess. Both roads end at the kernel, which creates the process, gives it memory, opens files and schedules it on the CPU. The only difference is what happens next: a GUI program draws a window, a command-line program prints text back to the terminal through standard output. So the desktop is not magic, it is just another program asking the kernel for the same services. On macOS and Linux the system calls are named fork and exec, but the idea is identical.

03 / Under the hood

Anatomy of a Command

C:\Users\you\my-app>

npm

Program

Which tool to run. The shell finds it on PATH.

install

Subcommand

What you want the tool to do.

vite

Argument

What to act on: here, the package name.

--save-dev

Flag / option

Starts with - or --. Changes the behavior: save it as a dev dependency.

PATH

The list of folders the shell searches. "is not recognized" means the program is not on PATH.

Exit code

Every program ends with a number: 0 means success, anything else is an error. CMD keeps it in %ERRORLEVEL%.

Streams

stdin goes in, stdout is normal output, stderr is error output. Redirect with > file.txt

Every command has the same grammar, whatever the shell. Take npm install vite --save-dev, a command you will type in this course. The first word is the program: npm. The shell looks for it in the folders listed in the PATH environment variable. Next comes a subcommand, install, which tells the tool what to do; not every program has subcommands, but npm and git do. Then the argument, vite, which is the thing to act on. Last, a flag or option: it starts with one or two dashes and changes the behavior. Here --save-dev records Vite as a development dependency in package.json. Three hidden concepts sit behind every command. PATH: if you ever see "is not recognized as an internal or external command", the program is not installed or not on PATH. Exit code: every program returns a number when it finishes, 0 means success; in CMD you can read it with echo %ERRORLEVEL%. Streams: input comes in on stdin, normal output goes to stdout, errors go to stderr, and you can redirect output into a file with the greater-than sign, for example dir > files.txt.

04 / Terminal families

Shells: The Languages You Type

Shell

Runs on

Since

What makes it different

cmd.exe

Windows

1987

Simple text commands and .bat batch files. Built into every Windows PC, but limited for real scripting.

PowerShell

Windows · macOS · Linux

2006

Passes objects, not plain text. Verb-Noun commands such as Get-ChildItem. Default profile in Windows Terminal.

Bash

Linux · macOS · Git Bash

1989

The classic Unix shell. Most tutorials, servers, Docker images and CI pipelines expect it.

Zsh

macOS · Linux

1990

Bash-like, with smarter completion, themes and plugins (Oh My Zsh). Default on Macs since 2019.

WSL + Bash

Windows 10 and 11

2016

A real Linux inside Windows. Run Bash and Linux tools without leaving your Windows PC.

When people say "types of terminal", they usually mean different shells, so let's meet the main ones. CMD is the classic Windows shell: simple, always there, good for basics, weak for serious scripting. PowerShell is Microsoft's modern shell. Its big idea is that commands pass objects, not plain text, so you can filter and sort real data. Commands follow a Verb-Noun pattern like Get-ChildItem, and since PowerShell 7 it also runs on macOS and Linux. Bash is the classic Unix shell from 1989. Most tutorials, servers, Docker containers and CI pipelines assume Bash, and on Windows you get it through Git Bash. Zsh is very similar to Bash but friendlier, with better completion and plugins, and it has been the default shell on macOS since Catalina in 2019. Finally WSL, the Windows Subsystem for Linux: not a shell itself, but a real Linux running inside Windows, so you can use Bash and Linux tools directly. Key message: the commands you type depend on the shell, not on the window.

Terminal Apps: Hosts for Shells

Windows Terminal

Windows 10 / 11

Tabs and panes for CMD, PowerShell and WSL. Default terminal in Windows 11.

Terminal and iTerm2

macOS

Terminal ships with every Mac; iTerm2 adds split panes and search.

GNOME Terminal

Linux

Default on Ubuntu and Fedora. KDE desktops ship Konsole instead.

VS Code terminal

Any OS

A terminal inside your editor: press Ctrl + ` and run npm next to your code.

Key idea

The app is only the window. The shell runs inside it, so one terminal can host many shells, one per tab.

The second meaning of "types of terminal" is the terminal application, the window itself. On Windows, use Windows Terminal: it has tabs and split panes, and one tab can run CMD while the next runs PowerShell or Ubuntu through WSL. It is the default terminal in Windows 11. On a Mac you get the built-in Terminal app, and many developers install iTerm2 for split panes and better search. On Linux, Ubuntu and Fedora ship GNOME Terminal, and KDE desktops ship Konsole. And the one you will use most in this course: the integrated terminal in VS Code. Press Control and the backtick key to open it, and you can run npm commands right next to your code. The key idea: the terminal app and the shell are independent. You can choose any window and run any shell inside it.

PowerShell understands many CMD and Bash names as aliases (ls, dir, cd, cls), but the options differ: ls -la works in Bash and fails in PowerShell.

Here is why the shell matters: the same task is spelled differently in each shell. Read a few rows aloud. To see where you are, CMD uses cd with nothing after it, PowerShell uses Get-Location, and Bash uses pwd, print working directory. To list files: dir, Get-ChildItem, ls. To create an empty file, Bash has touch, while CMD needs a small trick: type nul and redirect it into a file. PowerShell commands are long because they follow the Verb-Noun pattern, but PowerShell also ships short aliases, shown in brackets, so ls, dir, cd and cls work there too. The trap is the options: ls -la is perfectly normal in Bash but fails in PowerShell, because the alias only renames the command, not its flags. When you copy a command from a tutorial, first check which shell the tutorial is written for. Tip for the live demo: every command in the table is clickable and copies itself to the clipboard.

05 / Compare and choose

Pros and Cons

Desktop (GUI)

+ Strengths

  • Easy to discover: every option is on screen
  • Best for visual work: design, images, browsing
  • Forgiving: Undo, Recycle Bin, confirmation dialogs
  • Drag and drop, previews and thumbnails

− Weaknesses

  • Slow for repetitive work: 100 files = 100 clicks
  • Hard to automate or repeat exactly
  • Needs a screen; most servers have none
  • Every window costs memory and CPU

Terminal (CLI)

+ Strengths

  • Fast once you know the commands
  • Scriptable: one file can replay 100 steps
  • Works remotely over SSH, on servers and in CI
  • Home of front-end tools: npm, git, Vite

− Weaknesses

  • Steep start: you must remember commands
  • No undo: del skips the Recycle Bin
  • Error messages can be cryptic
  • Each shell speaks a different dialect

Professionals use both: the desktop to explore, the terminal to build and repeat.

An honest comparison, because neither one is better at everything. The desktop wins on discoverability: you can find features just by looking. It is the right tool for visual work like design in Figma, editing images or browsing. And it forgives mistakes with Undo and the Recycle Bin. Its weaknesses show up with repetition: renaming 100 files means 100 clicks, and you cannot easily record and replay what you did. Servers usually have no screen at all, and graphics cost memory. The terminal is the opposite. It is slow at first because you have to learn the commands, there is no undo, and the error messages can be cryptic. But once you know it, it is faster, it can be scripted, it works over SSH on remote servers and in automated CI pipelines, and it is where front-end tools like npm, git and Vite live. The takeaway: professionals use both. Explore with the desktop, build and repeat with the terminal.

Now the real numbers, from the Stack Overflow Developer Survey, the largest yearly survey of developers. In 2025, 48.7 percent of all respondents said they used Bash or another Unix shell, up from 33.9 percent in 2024. That is almost half of all developers, and the biggest jump among the languages on this chart. PowerShell grew too, from 13.8 to 23.2 percent. Notice what is missing: CMD is not even listed as a separate option in the survey. So to answer the question "do developers use CMD more often?": no. When developers script and automate, they reach for Bash or PowerShell; CMD is for the basics. The chart shows each language as two dots, violet for 2024 and blue for 2025, so the length of the line is the growth. Hover a row to see its numbers, or press the Table button for the full data. A word of caution: the people who answer the survey change from year to year, and the 2025 survey had fewer respondents than 2024, so read the change as a trend signal rather than an exact growth rate. Likely drivers are cloud deployment, Docker, CI pipelines and the new AI coding assistants that run in the terminal, but the survey does not measure the reasons.

Habits That Keep You Safe

Keys to Remember

completes file and folder names

Before You Press Enter

1

Read the prompt first: it shows which folder you are in.

2

del and rmdir /s skip the Recycle Bin. There is no undo.

3

Wrap paths with spaces in quotes: cd "My Projects"

4

Never paste a command you do not understand.

5

Use Run as administrator only when a task needs it.

Two sets of habits. First, the keys that make the terminal fast. Tab completes file and folder names, so you almost never type a full path; press it again to cycle through matches. The up and down arrows bring back previous commands. Control plus C stops a running program, for example a dev server or a ping that never ends. In CMD, F7 opens a small list of your recent commands. Control plus V pastes in Windows Terminal. And you can drag a folder from File Explorer into the terminal window to paste its full path. Second, the safety rules. Always read the prompt before pressing Enter, because it tells you which folder the command will run in. Remember that del and rmdir /s delete permanently, there is no Recycle Bin. Put quotes around paths that contain spaces, otherwise the shell sees two separate arguments. Never paste a command from the internet that you do not understand. And only open an administrator terminal when a task really requires it.

Quiz · 2 of 4 · click an answer

You are in C:\Users\you\my-app and type cd .. Where are you now?

Answer: A. Two dots always mean the parent folder, so cd .. moves exactly one level up. cd \ jumps to the root.

The correct answer is A, C:\Users\you. In every shell, two dots mean the parent folder and a single dot means the current folder, so cd .. goes up exactly one level. B would be the answer for cd backslash, which jumps to the root of the drive. If you have time, ask a follow-up: how would you get from my-app to the root in one command? Answer: cd \ in CMD.

Quiz · 3 of 4 · click an answer

In npm install vite --save-dev, what is --save-dev?

Answer: C. Flags start with - or --. This one records Vite as a development dependency in package.json.

The correct answer is C, a flag. Go back over the anatomy: npm is the program, install is the subcommand, vite is the argument, the package name, and --save-dev is a flag because it starts with dashes and changes how the command behaves. A dev dependency is a package needed while developing and building, like Vite, but not shipped to users. Option A describes npm, option B describes vite, and option D does not exist: npm always installs into the node_modules folder.

Quiz · 4 of 4 · click True or False

Lightning Round: True or False?

1

PowerShell passes objects between commands, not only plain text.

True. Its commands exchange structured objects with properties you can filter and sort.

2

del moves files to the Recycle Bin, so you can restore them.

False. del deletes permanently. There is no undo in the terminal.

3

A double-click and a typed command both ask the kernel to start a process.

True. Explorer and the shell both end up calling CreateProcess.

4

Windows Terminal can only run CMD.

False. It hosts CMD, PowerShell and WSL shells, one per tab.

Read each statement aloud, let the class shout true or false, then click their answer to reveal the explanation. One: true. PowerShell pipes structured objects with properties, which is its main difference from CMD and Bash, which pass plain text. Two: false. del deletes permanently and skips the Recycle Bin; this is exactly why the safety slide matters. Three: true. This is the big idea from the under-the-hood slide: Explorer and the shell both end up calling CreateProcess on the same kernel. Four: false. Windows Terminal is only a host; it runs CMD, PowerShell, WSL distributions like Ubuntu, and more, each in its own tab. Press R to reset the round.
